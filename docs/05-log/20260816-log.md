# Log 2026-08-16

## 09:45 — ชี้ขาดข้อขัดแย้ง 4 จุดกับเอกสาร Construction Project Control System

**Requirement ดิบ**: ผู้ใช้ส่งเอกสาร "ระบบควบคุมงานก่อสร้างเพื่อความสำเร็จของโครงการ (Construction Project Control System)" ซึ่งสังเคราะห์จาก 13 หน่วยเรียน มี REQ-F01 ถึง REQ-F28 พร้อม NFR ความต้องการด้านข้อมูล เกณฑ์ความสำเร็จ และข้อจำกัด แล้วสั่งให้เช็คกับสิ่งที่มี ผลการเทียบ: ครอบคลุมครบ 3 ข้อ บางส่วน 8 ข้อ ไม่มีเลย 17 ข้อ และพบข้อขัดแย้งจริง 4 จุดที่กระทบสเปคที่เขียนไปแล้ว จึงชี้ขาด 4 จุดนี้ก่อน

**การตัดสินใจ**: EXTEND — ทั้ง 3 สเปคยัง `draft` และข้อขัดแย้ง 3 จาก 4 จุดเป็นการชี้ขาดว่าข้อความเดิมข้อไหนชนะ ไม่ใช่การเพิ่มเรื่องใหม่ มีเพียง EAC ที่ผลิตข้อกำหนดใหม่จริง และตกอยู่ในขอบเขต "การคำนวณ" ที่ SPEC-001 ประกาศไว้แล้ว หมายเลข 004 จึงยังว่างไว้ให้ SPEC-004 (Project Lifecycle) กับ SPEC-005 (Planning & Scheduling) ตามแผนเดิม

**ข้อแม้ที่ analyst ยกขึ้นมา**: ถ้าเลือกเปลี่ยนแกน BCWS ไป derive จาก BOQ ทันที BR-003-09 บังคับไว้เองว่าต้องออก spec ใหม่ที่ supersede SPEC-001 ซึ่งจะพลิกการตัดสินเป็น SUPERSEDE ทันที — คำตอบที่เลือกไม่ได้ไปทางนั้น

**คำถามที่ถามและคำตอบ**:

- วิธีแก้เอกสาร → **EXTEND ทั้ง 3 สเปค** (ไม่เลือกออก SPEC-004 บันทึกการชี้ขาดแยก หรือแก้เฉพาะ SPEC-001)
- ข้อขัดแย้ง 4 (REQ-F11 BOQ bottom-up) → **เลื่อน REQ-F11 คง BCWS กรอกมือ** (ไม่เลือกทำโมดูล BOQ แบบกั้นไม่ให้ต่อเข้า EVM, ไม่เลือกเปลี่ยนแกนทันที, ไม่เลือกให้ระบบตรวจทานเทียบงบต่องาน) เหตุผลคือ REQ-F11 เป็นเรื่องการประมาณราคา ไม่ใช่การวัดผล และการรับเข้ามาตอนนี้ขยายขอบเขตของรอบที่ยังไม่ได้เริ่มลงมือ
- ข้อขัดแย้ง 2 (0.95 vs 0.9) → **แยกคนละระดับ** 0.9 เป็นเกณฑ์ปฏิบัติการรายโครงการรายงวด ส่วน 0.95 เป็นเป้าหมายระดับพอร์ตโฟลิโอที่อยู่ใน `02-plan` (ไม่เลือกยกเกณฑ์เป็น 0.95, ไม่เลือกเพิ่มระดับสีส้ม, ไม่เลือกลดเป้าเป็น 0.9) — BR-001-05 และ BR-002-06 ไม่ต้องแก้แม้แต่ตัวเดียว
- ข้อขัดแย้ง 1 (REQ-F09 คำนวณอัตโนมัติ) → **คงกระบวนการสองขั้น ปฏิเสธส่วนอัตโนมัติพร้อมบันทึกเหตุผล** (ไม่เลือกให้ระบบคำนวณตัวเลขตั้งต้นให้ PM, ไม่เลือกรับตามตัวอักษร)
- สูตร EAC → **EAC = BAC / CPI** (ไม่เลือก ACWP + (BAC − BCWP), ไม่เลือกสูตรที่หารด้วย CPI × SPI, ไม่เลือกให้ PM เลือกสูตรเอง) เพราะใช้เฉพาะค่าที่มีอยู่แล้ว ไม่ต้องเพิ่มแหล่งข้อมูล และให้ค่าเดียวต่อโครงการจึงเทียบข้ามโครงการได้
- ตัวพ่วงกับ EAC → **เพิ่ม ETC และ VAC แต่ไม่ผูกกฎเตือนใน SPEC-002** (ไม่เลือกเพิ่มเฉพาะ EAC, ไม่เลือกเพิ่มกฎเตือน, ไม่เลือกเพิ่ม TCPI) เพราะเมื่อ EAC = BAC/CPI กฎเตือนบน EAC จะเป็นการเตือนเรื่องเดิมด้วยชื่อใหม่ ควรรอจนกว่าจะใช้สูตรที่มีข้อมูลอิสระเข้ามา
- สิทธิ์เห็น EAC → **PM และผู้บริหาร เพิ่มเข้ารายการปิดของ BR-003-12** ไม่เปิดให้เจ้าของโครงการ (ไม่เลือกจำกัดเฉพาะ PM, ไม่เลือกเปิดให้ลูกค้า) เพราะ EAC เปิดเผยตรง ๆ ว่าผู้รับเหมาจะใช้เงินเกินงบเท่าไร ซึ่งเข้านิยาม "ต้นทุนภายใน" ที่ BR-003-01 ห้ามเด็ดขาด

**สิ่งที่เปลี่ยน**:

- **SPEC-001** — เพิ่ม FR-001-17 (EAC), FR-001-18 (ETC/VAC), FR-001-19 (แสดงบนการ์ดพร้อมคำอธิบายไทย), BR-001-11 (สูตร EAC และที่มาของ BAC ตาม baseline เวอร์ชันที่มีผล), BR-001-12 (แสดง "—" เมื่อ CPI คำนวณไม่ได้), เกณฑ์การยอมรับข้อ 10–12, และหัวข้อใหม่อธิบายว่าทำไม 0.9 กับ 0.95 อยู่ร่วมกันได้
- **SPEC-003** — BR-003-12 เพิ่ม EAC/ETC/VAC เข้ารายการปิด, เกณฑ์การยอมรับข้อ 11 ระบุชัดว่าเจ้าของโครงการเรียกค่าพยากรณ์ไม่ได้, หัวข้อไม่อยู่ในขอบเขตเพิ่มโมดูล BOQ, ข้อ 13 ผูก REQ-F11 เข้ากับ spec ลูกลำดับที่ 5, และเพิ่มตารางบันทึกข้อกำหนดที่ถูกปฏิเสธพร้อมเหตุผล
- **SPEC-002** — **ไม่ต้องแก้อะไรเลย** เพราะคำตอบข้อขัดแย้ง 2 เลือกทางที่ไม่ขยับเกณฑ์ และคำตอบเรื่อง EAC เลือกไม่ผูกกฎเตือน แม้ analyst จะเสนอ EXTEND ทั้ง 3 ไฟล์ก็ตาม

**สิ่งที่ตัดออกจากข้อเสนอของ analyst**: analyst เสนอ FR-001-20 สำหรับการบันทึก EAC/ETC/VAC ลง snapshot — ไม่เพิ่ม เพราะ FR-001-09 ระบุว่าบันทึก "ค่าทั้งหมด" อยู่แล้ว การเพิ่ม FR ใหม่จะเป็นข้อกำหนดซ้ำ แถว BL-001-26 จึงอ้าง FR-001-09 แทน

**ผลต่อ backlog**: เพิ่ม BL-001-23 ถึง BL-001-26 และ BL-003-32 รวมทั้งหมด 79 รายการ — ข้อขัดแย้งที่ 1, 2 และ 4 ไม่ผลิตรายการใหม่เลย เพราะเป็นการยืนยันข้อกำหนดเดิมและบันทึกเหตุผล ไม่ใช่การเพิ่มสิ่งที่ต้องสร้าง
